# Observed operation coverage

2026-09-14, `my_v` only. Every operation point uses one observed-coverage pipeline.
Catalog-feature result assertions are inserted by code; only taxonomy-missing
feature assertions and observers are generated by the Verifier.

## What changed

```text
Architect: feature semantics, signals, roles, dimensions and integer types
  -> Code: select known taxonomy features and assertion/coverage machinery
  -> Verifier: choose operation point/template/channel; bind non-unique fields;
       add custom functions only when no template exists
  -> Code: validate connections; instantiate reusable bins or accepted custom bins
  -> Definition review: inspect bins, sources, custom bodies/helpers and assertions
  -> Saved TB block: capture every declared interface signal once
       one immutable snapshot shared by assertions and coverage
       reusable template OR generated observer(values, state) -> scalar observation
  -> cocotb-coverage CoverPoint: match value against bins and increment hits
  -> Existing coverage gate: zero-hit required bin still fails
```

The saved TB monitor supplies an observed value; **cocotb-coverage records the bin hits**.
It does not poll DUT signals independently. The observer uses the same stable
pre-active-edge phase as existing protocol sampling, and reset-edge cancellation
is shared. Drivers must obey the existing phase discipline; arbitrary mid-half-cycle
signal changes are not made safe by this change.

Templates live beside this file in `sampling_templates.yaml`.
Executable reads, signed decoding and value classification live in
`sampling.py`. Actual CoverPoints still use `../cocotb_model.py`.

| Implementation | Observed data | Bins |
| --- | --- | --- |
| `custom` | Runtime-read field snapshot, prior observed per-point state | Generated feature-specific predicates, definition-reviewed |
| `dimension` | One direct unsigned dimension field | Contract minimum/interior/maximum, or fixed |
| `integer_operand` | One accepted operand and declared integer type | Zero, positive, negative if signed, minimum, maximum |
| `boolean_mode` | Actual one-bit mode encoding | Only declared applicable enabled/disabled modes |
| `discrete_mode` | Actual selector encoding | Declared legal modes |
| `tile_shape` | Accepted dimensions and declared tile parameters | Reachable full and partial tile classes |
| `channel_stall` | Completed stall length returned by the code-owned protocol assertion | None, one cycle, 2–4 cycles, at least 5 cycles; sampled on transfer |
| `integer_add_overflow` | Actual aligned a/b input pair and integer types | Reachable overflowing and non-overflowing input scenarios |

Bin overlap is intentional where a boundary is also an operand value class.
Tile sampling excludes dimension encodings outside the declared legal bounds.
Reset/test boundaries cancel pending stalls; they do not manufacture a released
stall witness. Modes absent from the contract are not forced into coverage.

## TB connection example

Suppose a contract says `multiply` receives M/N/K as direct unsigned fields in
`cmd_payload`, on the `command` channel's accepted transfer. These names, bit
positions and widths are illustrative, not fixed naming conventions.

```python
# Existing operation_coverage contains local points m, n, k with concept dimensions.
# Each point retains its normal operation ID, concept and required source.
OPERATION_SAMPLING_BINDINGS = [
    {"operation": "multiply", "point": "m", "template": "dimension",
     "event": "transfer", "channel": "command", "dimension": "M",
     "fields": {"value": {"signal": "cmd_payload", "lsb": 0, "width": 7}}},
    {"operation": "multiply", "point": "n", "template": "dimension",
     "event": "transfer", "channel": "command", "dimension": "N",
     "fields": {"value": {"signal": "cmd_payload", "lsb": 7, "width": 7}}},
    {"operation": "multiply", "point": "k", "template": "dimension",
     "event": "transfer", "channel": "command", "dimension": "K",
     "fields": {"value": {"signal": "cmd_payload", "lsb": 14, "width": 7}}},
]

# Verifier constructs expected_outputs and independently collects observed_outputs.
# Code inserts this helper and performs the selected catalog-feature comparison:
stimulus_id = _contract_record_checked_stimulus(
    "directed", actual_inputs, expected_outputs, observed_outputs,
    operations=("multiply",), label="directed_boundaries",
)
sample_operation("multiply", {}, "directed", stimulus_id)
```

For these points, the TB snapshot supplies the actual field and the sampler accepts
it only on `valid && ready`,
derives bounds from the named contract dimension, and supplies the observed number
to the library. A TB-supplied `{"m": 64}` cannot hit any point. The hook remains for
checked-job ledger association and the existing randomized-job policy, not to
trigger coverage. Its old name/signature are kept; all supplied fields are ignored.

Other connection options:

- A field can use exact `signal`, or exact declared `channel` + `role`; optional
  `lsb`/`width` selects a slice. No fuzzy signal-name matching is added.
- For a declared transfer channel, `integer_operand` may omit `fields` only when
  that channel has exactly one whole `payload` signal with literal width and
  signedness exactly matching the named contract `data_type`. `boolean_mode`
  may omit `fields` only for one unsigned one-bit whole payload. In these cases
  code chooses the signal by role; the Verifier still chooses the operation
  coverpoint, template and channel. The resolved plan/report marks
  `field_binding_origin: code_unique_role_and_type`.
- If the channel has multiple payloads, a packed payload, symbolic width or
  unknown signedness, code refuses to guess. The Verifier must name an explicit
  field/slice. In particular, GEMM's packed M/N/K configuration is not inferred
  from the `framing` prose or signal names.
- Optional literal `guards` are `[{"field": <source>, "equals": <encoding>}]`.
  They select actual observable operation/mode encodings on a shared interface.
  Their interpretation and stability must match the contract; they do not track
  arbitrary multi-job association automatically.
- `event: clock` omits the transfer channel. Use only for explicitly combinational
  or clock-observed semantics. It proves observation, not command acceptance.
- `integer_operand` names `data_type`; selected width must match the declared type.
  Signed values decode as two's complement.
- `boolean_mode`/`discrete_mode` require applicable `legal_values` encodings.
- `tile_shape` maps exact dimension names to sources in `fields`, and those names
  to positive literal-default contract parameters in `tile_parameters`.
- `integer_add_overflow` has fields `a`/`b`, `operand_types: {a: ..., b: ...}` and
  `result_type`. Inputs must be observable as the aligned pair for the event.
  It covers an input scenario; it does **not** check correct result/flag handling
  or represent full GEMM accumulation overflow.

## Feature missing from the pool or reusable templates

LLM-generated custom observers use **the same TB snapshot and CoverPoint**,
not a driver-side fallback. A new feature does not need a registry/taxonomy edit.
For example, a novel accepted-input class can be defined as follows (the interface
must actually expose the aligned a/b pair on this accepted channel):

```python
OPERATION_SAMPLING_BINDINGS = [{
    "operation": "compute", "point": "large_input_sum", "template": "custom",
    "observer": "observe_large_sum", "event": "transfer", "channel": "operands",
    "fields": {"a": {"signal": "input_a"}, "b": {"signal": "input_b"}},
}]

def observe_large_sum(values, state):
    return values["a"] + values["b"] > 15

# The point's ordinary generated bin predicates are eq(False) and eq(True).
# No call to a coverage-hit API is needed; @contract_coverage invokes the function.
```

The backend supplies a read-only field mapping from that snapshot, not a DUT/coverage handle. Optional
`field_types` names declared integer types for signed decoding. A custom function
returns a finite scalar; `None` delays sampling until the relevant observed event.
It must be a local synchronous function with two arguments and no decorators or
default arguments. Local helper bodies are included in definition review.

For whole-job/multi-channel features, bind observable valid/ready/data/config/
completion fields with `event: clock`, and maintain accepted-value/job state in
the provided per-point dictionary. State is cleared on reset and test boundaries.
`channel_stall` does not maintain a second counter: it reuses the completed length
already measured by the fixed protocol assertion. A mode-qualified stall needs a
custom observer because the generic protocol observation is deliberately unguarded.
Examples include matrix patterns or accumulation classes derived from accepted
operand streams. Do not use driver loops, planned stalls or recorded expected
outputs as coverage observations. Custom points are activated automatically from
their owning test module's declaration; another module's observer does not leak.

## Boundaries and repair

The declaration is parsed with `ast.literal_eval`, never executed. Undeclared
signals/channels/types/dimensions, conflicting bindings, invalid slices and
malformed metadata become existing counted Verifier corrections. Elaborated
handle widths are checked at runtime for symbolic ports. The existing budget,
Only Verifier may turn an unresolved executable expectation into an Architect
question. Definition review reports TB defects back to Verifier, and Debugger treats
the approved TB as frozen during RTL repair.

Definition review sees effective bins, static connections and complete custom
observer/helper bodies, not hit counts or stimulus schedules. Code validates
structure/reference/width; **the binding's semantic correctness still needs
contract-based review**. A wrong declared source can still be structurally valid.

Encodings without a reusable template, nonlinear numeric formats, GEMM accumulation, whole-matrix
value patterns, fused operation/order/job-association semantics and novel features
use generated custom observers in this same pipeline. Every operation point needs
a binding; old unbound TBs require a counted Verifier correction before simulation,
not silent legacy sampling. Saved old experiment artifacts remain untouched.
We have not supplied a prebuilt observer for every feature or proved arbitrary
generated Python's semantics. Runtime controls observation inputs/invocation and
the library records hits; it cannot prove a custom scalar return matches its
claimed meaning. A constant True or driver-global dependency can still be wrong
custom code and must be caught by contract-based review. This interface is not
a Python security sandbox. Existing generated-code capability checks still apply.
The independent golden and stimulus remain LLM-authored. The pipeline owns the
catalog-feature comparison itself. A taxonomy-missing accelerator feature retains
the existing LLM custom-assertion path and definition review. No new golden
sanity/RAG step is introduced.

## Artifacts and verification

Each generated run saves the literal connections in
`verification/operation_sampling_bindings.yaml`, and effective points in
`operation_coverage_plan.yaml` and `combined_coverage_plan.yaml`. Simulation and
missing-bin feedback use that same effective plan. Raw candidate metadata remains
in `verifier_result.json` for provenance, not as the authoritative auto-point bins.

Coverage JSON exposes `sampling_origin` and `operation_sampling` (counts and last
observed values). The checked-job ledger identifies runtime-sampled points and
ignored supplied fields instead of presenting those supplied values as evidence.
Existing ledger bin-to-job attribution remains temporal summary evidence, not a
new proof of precise association for concurrent jobs.

Offline tests include actual transfer gating, contract-adaptive bins, signed
decoding, guard filtering, real stall lengths, reset cancellation, symbolic widths,
illegal shape filtering, literal validation, custom extensions, persistence,
definition review, simulation-node integration and missing-bin feedback.
A real Verilator/cocotb smoke test drives 17 small 4-bit addition jobs and checks
outputs independently: **1 test PASS, 12/12 cocotb-coverage bins hit**, including a
custom observer and reusable templates together. Deliberately
false TB coverage fields are ignored. This is a focused integration smoke test,
not a new LLM-generated GEMM experiment or a claim of full-pipeline completeness.
