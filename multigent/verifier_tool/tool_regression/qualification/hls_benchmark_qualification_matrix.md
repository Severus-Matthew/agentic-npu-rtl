# Real HLS golden benchmark qualification matrix

Target: `gemm_golden/int8_gemm.v` with the frozen [`int8_gemm_hls_golden`](../benchmarks/int8_gemm_hls_golden/) architecture/interface contracts. The TB must be generated by `render_contract_generated_block`, without a hand-written replacement. Run each mutant against that generated TB first, require the intended named diagnostic or exact target-bin miss, then require the unchanged/corrected HLS RTL to pass **all required bins, assertions, and stimulus-ledger checks**. `✓` means that an assertion/checker strict pair completed. `E` means that a coverage row has both real HLS observed-hit evidence and an exact per-bin evidence-ablation rejection; it is intentionally not mislabeled as an RTL mutant. `S` marks earlier manually assembled smoke-TB detection only; `D` marks a deterministic driver rejection and `T` a timeout only. None of `S/D/T` counts as strict qualification. `—` means not yet qualified. Start with `—` targets.

Current generated plan after the [contract-to-RTL audit](../benchmarks/int8_gemm_hls_golden/CONTRACT_AUDIT.md): **83 runtime coverage containers, 71 of them containing 152 required bins**. The 12 containers with no required bins remain harmless runtime structure but are excluded from the qualification denominator. The plan includes the three real HLS two-bit LOCK bindings plus observable control-plane job lifecycle, reset-abort phase, and post-reset-purity coverage. The unchanged HLS RTL passes the complete generated TB with **152/152 required bins, zero assertion failures, and a PASS ledger with 20 stimuli** (12 directed, 8 randomized). Every required bin has also been independently ablated while retaining the aggregate PASS fields; all **152/152 evidence-ablation cases** were rejected for the exact missing bin. Required bins are credited from observed DUT transactions, not planned scenario labels.

The no-simulation preparation catalog at [`prepared_qualification_catalog.json`](../benchmarks/int8_gemm_hls_golden/prepared_qualification_catalog.json) accounts for all 134 applicable targets below (71 coverage obligations with required bins plus 63 assertion/checker targets). All **63/63 concrete assertion/checker targets are strictly qualified**. The exact-anchor RTL registry contains **62/62 executed mutants**: 51 are detected by named assertions, seven by the tool-owned operation golden model, and four by deterministic driver/adapter guards. On 2026-09-29 all **62/62 named mutants** qualified against one generated-TB SHA-256 with zero unqualified cases and zero runner errors. Environment-owned protocol channels likewise completed **21/21 driver-fault qualifications** with zero unqualified cases and zero runner errors. Detection attribution is recorded separately so a pointer-range or WSTRB driver rejection is never mislabeled as lifecycle/protocol assertion qualification. Each illegal LOCK mutant raises the exact feature diagnostic, while each original RTL passes 152/152. `ready_valid_stability` is represented once by each executable channel-level `stall_stability` checker, full AXI's two-bit RESP has no reserved encoding, and channel-absent rules are no longer emitted as fake targets.

Qualification-only protocol fault code is confined to `tool_regression/benchmarks/int8_gemm_hls_golden/`; production AXI4, AXI4-Lite, and lifecycle drivers contain no fault-plan lookup or mutation branch. The benchmark-local bootstrap covers AXI4 response ID, same-ID ordering, AXI4 response stall release, AXI4-Lite unpaired write, AXI4-Lite request stall release, and the narrow-transfer active-lane guard. Every negative raises its intended feature diagnostic and every applicable scenario-positive run passes 152/152.
