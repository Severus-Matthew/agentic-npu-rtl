# u55c-inspired int8 GEMM (4x4x4, AXI4-Lite)

A hand-authored frozen contract plus a fully generated cocotb testbench,
produced entirely by calling `verifier_tool`'s deterministic Python API
directly — **no Architect or Verifier LLM call was made**. This exists as a
`verifier_tool` benchmark fixture: a compact, real, end-to-end exercise of the
contract-metadata pools, feature plans, and the fully automatic code-owned
campaign, useful both as a worked example and as a regression fixture after
future refactors (including the domain-first reorganization this fixture was
used to sanity-check).

## Where the design idea comes from

Loosely inspired by the real HLS kernel at
[`gemm_golden_hls/gemm_hls/int8_gemm.cpp`](../../../../gemm_golden_hls/gemm_hls/int8_gemm.cpp)
(a 32x128, K=64 packed-int8 GEMM accelerator for the AMD/Xilinx Alveo U55C
card; its Vitis-HLS-generated RTL is in
[`gemm_golden/`](../../../../gemm_golden/)). This fixture keeps that kernel's
core arithmetic shape — signed int8 `A`/`B` operands, exact product, signed
int32 accumulation, **no bias, no activation** — but deliberately differs from
it in two ways, so it stays a compact, readable AXI4-Lite example. **This
fixture is not a replica of the real kernel; the faithful one is
[`../int8_gemm_hls_golden/`](../int8_gemm_hls_golden/)** (see the note after the
table):

| | Real u55c kernel | This fixture |
|---|---|---|
| Dimensions | M=32, K=64, N=128 | M=K=N=4 (small enough to be a fast, readable example) |
| Control | Vitis-generated AXI4-Lite register control (`ap_ctrl_chain` per `gemm_golden/int8_gemm_control_s_axi.v`: `ap_start` bit 0, `ap_done` bit 1, `ap_idle` bit 2, `ap_continue` bit 4) | One `valid_ready_handshake` command channel (the `job_acceptance` policy this fixture selects; the [`lifecycle_policy_pool`](../../pool/lifecycle_policy_pool/README.md) also implements `control_plane_sequence` for register-started jobs) |
| Bulk data movement | Three independent full-burst AXI4 manager ports (`gmem_a`/`gmem_b`/`gmem_c`), each with bit-packing (see the kernel's `load_a`/`load_b`/`store_c`) | One shared AXI4-Lite manager group (`m_axi`) serving sequential single-beat reads (A fully, then B fully) then writes (Y). The tool also supports generic full-AXI4 memory mappings and the `packed_encoding` serialization; this fixture intentionally stays AXI4-Lite so it remains compact and readable. |

In other words: this is "roughly based on" the real kernel's *math*, adapted
to a compact transport. The capabilities a faithful replica needs now exist:
the `control_plane_sequence` lifecycle policy for register-started jobs, the
`packed_encoding` serialization for the kernel's A/B memory layouts, and
multi-port full-AXI4 memory mapping and driving. They are exercised by the
separate frozen contract [`../int8_gemm_hls_golden/`](../int8_gemm_hls_golden/)
(built by its `build_contract.py`, audited in its `CONTRACT_AUDIT.md`), which
targets the real RTL in `gemm_golden/`; see [`../README.md`](../README.md) and
[`../../HLS_GOLDEN_BENCHMARK_MATRIX.md`](../../HLS_GOLDEN_BENCHMARK_MATRIX.md)
for its status. This 4x4x4 fixture was not changed to match.

## Files

| File | What it is |
|---|---|
| `build_contract_and_tb.py` | The script that builds everything below. Re-run it any time to regenerate deterministically (`python multigent/verifier_tool/benchmark/u55c_inspired_int8_gemm_4x4x4/build_contract_and_tb.py`, with the repo root on `PYTHONPATH`). Zero API calls. |
| `architecture_contract.yaml` | The hand-authored frozen contract: one `gemm` operation, `coverage_family=matrix_multiply`, full `arithmetic` (`integer_matrix_multiply`) and `lifecycle_policy` declarations, `serialization` on every data object. |
| `interface_contract.yaml` | One `cmd_chan` (opcode + three base-pointer metadata fields) plus one shared `m_axi` AXI4-Lite manager group (all 5 channels), with `protocol_group=`/`protocol_channel=`/`protocol_field=`/`protocol_capability.*=` tags exactly as [`role_pool/README.md`](../../pool/role_pool/README.md) documents. |
| `module_manifest.json` | One top module, ports generated 1:1 from `interface_contract.signals`. |
| `acceptance_criteria.yaml` | Minimal functional/verification/rtl/fpga_handoff criteria (not machine-validated by any current code path — free text). |
| `test_gemm_automatic.py` | The generated cocotb test file — see below. |
| `functional_coverage_plan.json` | The merged (interface + operation + lifecycle) coverage plan a real run needs — see "Running it for real" below. |
| `functional_coverage_report.json` | A **zero-hit baseline** report — the exact shape `tracker.report()` produces, with `status: FAIL`, `required_bins: 89`, `hit_bins: 0` **as checked in**. That file was generated by an earlier tool version: re-deriving the merged plan from the checked-in contracts with the current code (read-only check) still gives 37 obligations but `required_bins: 74` from a fresh `InterfaceCoverageTracker`, so the checked-in `functional_coverage_plan.json` / `functional_coverage_report.json` / `.cocotb-coverage.yml` are stale relative to the current tool until `build_contract_and_tb.py` is re-run. It is still the shape a real `InterfaceCoverageTracker` reports before any stimulus has run, because no RTL exists for this benchmark's DUT. A real simulator run overwrites this same shape, at whatever path `NPU_FUNCTIONAL_COVERAGE_REPORT` names, with real hit counts. |
| `functional_coverage_report.cocotb-coverage.yml` | `cocotb_coverage`'s own native export, written automatically alongside the JSON report by `InterfaceCoverageTracker.write_report()` — same zero-hit baseline, different (upstream-library) format. |

## How the TB was actually produced (no LLM)

`build_contract_and_tb.py` calls, in order, exactly the same deterministic
functions [`ARCHITECT_INTEGRATION.md`](../../ARCHITECT_INTEGRATION.md) and
[`VERIFIER_INTEGRATION.md`](../../VERIFIER_INTEGRATION.md) document as the
reference-validation and code-generation surface:

```python
validate_interface_signal_roles(interface_contract)          # role_pool
validate_interface_semantics(interface_contract)              # role_pool
validate_architecture_operation_features(architecture_contract)   # operation/coverage + feature_plans
validate_architecture_lifecycle_policies(architecture_contract)   # lifecycle_policy_pool
validate_architecture_operation_arithmetic(architecture_contract) # operation_metadata

operation_metadata = build_architect_operation_metadata(architecture_contract, interface_contract)  # operation_metadata
interface_plan = build_interface_coverage_plan(interface_contract)  # protocol/coverage
support = automatic_campaign_support(operation_metadata, architecture_contract)  # orchestration/campaign

render_contract_generated_block(  # orchestration/instrumentation
    interface_plan, architecture_contract,
    include_automatic_campaign=support["supported"],  # True for this fixture
)
```

`automatic_campaign_support(...)` reports `{"supported": true}` for this
design — every input/output binding resolves to a supported wire adapter
(one-element-per-transfer `dense_tensor` serialization over the shared
AXI4-Lite group, with all six required `protocol_capability.*` tags present),
so `render_contract_generated_block` was called with
`include_automatic_campaign=True`. That means `test_gemm_automatic.py` is
**entirely** the code-owned generated block — there is no Verifier-authored
region at all, no `# === STIMULUS AND COVERAGE INTENT ===` section, and no
hand-written test function. Its final `_contract_automatic_verification_campaign`
test calls `run_code_owned_verification_campaign(...)` directly, which drives
every reachable directed vector plus randomized jobs, checks each against the
canonical GEMM classifier in
[`pool/operation_metadata/canonical.py`](../../pool/operation_metadata/README.md), and
reports functional coverage — with zero LLM involvement at any stage from
contract to executable test.

This fixture was **not** run against real RTL (there is no synthesizable
design behind this hand-authored contract) — it only proves the contract is
valid and the deterministic TB-generation path produces a complete,
`compile()`-clean cocotb test file. Running it against a real DUT would need
an actual RTL implementation of `u55c_inspired_int8_gemm_4x4x4_top` first.

## Running it for real: the coverage-plan dependency

`test_gemm_automatic.py` is complete and importable on its own, but it is
**not standalone-executable**: the `@_contract_coverage()` decorator on
`_contract_automatic_verification_campaign` calls `get_coverage_tracker()`
the moment the test actually runs (`orchestration/runtime.py`), and that
unconditionally requires the `NPU_FUNCTIONAL_COVERAGE_CONFIG` and
`NPU_FUNCTIONAL_COVERAGE_REPORT` environment variables — the first must point
at a JSON file shaped exactly like `merge_coverage_plans(interface_plan,
operation_plan)`'s output. Without it, the test raises `CoverageRuntimeError`
before any stimulus runs at all. `functional_coverage_plan.json` in this
folder **is** that file, built the same way: `synthesize_code_owned_operation_coverage`
derives the operation coverage from the frozen contract alone (no
Verifier-authored declarations exist for this design), and
`operation_plan_for_tests` — not `build_operation_coverage_plan` directly —
is the function that attaches `bindings.sampling = {"template":
"canonical_job"}` to each of the three operation obligations, which
`OperationSamplingMonitor` hard-requires (a real, easy-to-miss step:
`build_operation_coverage_plan` alone builds correct coverpoints/bins but
never attaches this). `build_contract_and_tb.py` also constructs a real
`InterfaceCoverageTracker` against this plan and immediately `close()`s it,
which is what produces `functional_coverage_report.json` — proving the plan
is actually usable, without needing a live simulator, and leaving behind the
literal zero-hit baseline shape a real run's report starts from.

To actually run it for real (once real RTL exists for the top module) and
get a report with genuine hit counts instead of the zero-hit baseline
checked into this folder:

```bash
export NPU_FUNCTIONAL_COVERAGE_CONFIG=$(pwd)/multigent/verifier_tool/benchmark/u55c_inspired_int8_gemm_4x4x4/functional_coverage_plan.json
export NPU_FUNCTIONAL_COVERAGE_REPORT=/path/to/output/report.json
# NPU_STIMULUS_LEDGER_REPORT is optional
make SIM=... TOPLEVEL=u55c_inspired_int8_gemm_4x4x4_top MODULE=test_gemm_automatic  # or your cocotb runner of choice
```

## Regenerating

```bash
PYTHONPATH=<repo-root> python multigent/verifier_tool/benchmark/u55c_inspired_int8_gemm_4x4x4/build_contract_and_tb.py
```

Edit `build_contract_and_tb.py`'s `build_architecture_contract()` to change
dimensions, add a bias/activation stage, or (with the caveats above) attempt
a closer replica of the real kernel's interface once this tool supports it.
